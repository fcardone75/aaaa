Detailed Description

In the IBM Cloud environment (account: ....., namespace: .....), we have observed that the ingress controller is not able to route traffic to the target service.

Upon investigation, it appears that the root cause is a DNS resolution failure for the service name within the cluster. Specifically, when running a test pod based on Alpine Linux and executing:

wget http://....

the response is “bad address”, indicating that the service name cannot be resolved via DNS.

However, when directly accessing the service via its ClusterIP with:

wget http://....

the request is successful, and the correct index.html from the nginx service is returned as expected.

This confirms that the service is up and responding, and that the issue is specifically related to internal DNS name resolution within the Kubernetes cluster.

Environment:
	•	IBM Cloud
	•	Account: ......
	•	Namespace: .....
	•	Non-production
